# Janiverse platform audit — partial migration

This review does **not** certify the entire extension as compliant with the requested supported-interface boundary. UUID generation is migrated; the existing gaps below remain unresolved. The user subsequently authorized local testing and a staging push after successful validation. No main merge or release is included.

## What changed

Baseline: staging `c397c41`, extension version 0.8.43. Release version is unchanged.

- Removed `src/uuid.ts` and its obsolete custom-generator test.
- Added a small backend entry, `src/uuid-host.ts`, and `src/uuid-client.ts`, using only the verified UUID/messaging contracts below.
- Migrated all six production generator call sites: `character-delete.ts` (deletion operation ID), `prompt-settings.ts` (two prompt-block IDs), `profile-chats.ts` (panel ID), `profile-lorebooks.ts` (reader IDs), `soundtrack-field.ts` (input/help IDs), and `tutorial-annotations.ts` (SVG marker IDs).
- Propagated context/cancellation through character creation/profile, soundtrack editor, and all three tutorial callers. Accessible labels remain available while host IDs are pending; interrupted operations never create replacement UUIDs.
- Added SDK 0.6.79 as an exact development dependency and updated the lockfile. Added the backend manifest entry/build target; rebuilt both shipped bundles.
- Replaced the obsolete AGENTS instruction requiring a custom crypto UUID helper. The user's explicit branch and publishing instructions take precedence over the default workflow.
- Added `bun run typecheck`, a strict production-source tsconfig, TypeScript 7.0.2, and CSS module declarations. Fixed optional settings captured by asynchronous tutorial callbacks and mount callback element types.
- Character creation, persona creation, and attached-music updates now use explicit frontend/backend messages and permission-gated `spindle.characters.create/get/update` / `spindle.personas.create`. Removed their raw application REST calls. Only the host-supplied account/document identity is used; no arbitrary method dispatcher was added. Existing Characters/Personas grants cover these operations.
- Portraits now use the documented Spindle tus upload endpoint, followed by scoped `spindle.uploads.get/delete` and permission-gated `spindle.characters.setAvatar`. The previous raw `/characters/:id/avatar` call is removed. Preserved the 9.9 MiB limit, original file bytes, local preview/drop support, cancellation, and retry of only the already-created card's portrait. No image bytes enter frontend/backend messages. Accepted staged uploads are deleted after processing; transfers interrupted before backend processing rely on the documented host expiry.
- Music updates fetch fresh card data and submit only the `janiverse` extension namespace; the documented shallow merge retains other namespaces and attached lorebooks. Cancellation stops waiting and ignores late replies; it does not claim to undo a host write already in progress. Ambiguous creation results continue to block blind duplicate creation.
- Missing optional chat mutation methods now show native-editor guidance. Chat deletion rejects an explicit `false` result while preserving the current host's successful `void` return (a verified SDK/host discrepancy).
- Updated README compatibility requirements to agree with the manifest. Release versions and branch names are unchanged.

## Verified contracts and compatibility

Reviewed on 2026-11-10 against the current official SDK `lumiverse-spindle-types@0.6.79` (npm registry and official repository agree), SDK commit `fe412d6e378466dfe42a2df16649fa037e428c06`, and official Lumiverse staging commit `68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1` (version 1.3.0). Official main at `45f8db563e1c314ed2aab227613b28eb5ea1084e` reports 1.2.5 and does not contain this UUID contract. This is snapshot evidence, not a claim about the first release that will include the feature.

- [Backend UUID documentation](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/backend-api/uuid.md): `await spindle.uuid.v4(): Promise<string>`; free, no user ID or permission. `v7()` is also documented but unnecessary here.
- [Published UUID types](https://github.com/prolix-oc/lumiverse-spindle-types/blob/fe412d6e378466dfe42a2df16649fa037e428c06/src/uuid.ts), [SpindleAPI.uuid](https://github.com/prolix-oc/lumiverse-spindle-types/blob/fe412d6e378466dfe42a2df16649fa037e428c06/src/spindle-api.ts), [frontend context](https://github.com/prolix-oc/lumiverse-spindle-types/blob/fe412d6e378466dfe42a2df16649fa037e428c06/src/dom.ts): UUID generation is backend-only; the frontend context has no UUID generator.
- [Frontend messaging](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/frontend-api/backend-communication.md) and [backend messaging/routing](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/backend-api/frontend-communication.md): `ctx.sendToBackend(payload)`, `ctx.onBackendMessage(handler)`, `spindle.onFrontendMessage((payload,userId,frontendSessionId) => ...)`, and `spindle.sendToFrontend(payload,userId,{frontendSessionId})`.
- [Manifest/version rules](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/getting-started/manifest.md) and [permissions](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/getting-started/permissions.md).
- [Character CRUD and extension merge rules](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/backend-api/characters.md), [persona CRUD](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/backend-api/personas.md), and [host content handlers](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/src/spindle/worker-host-content-api.ts) verify the migrated writes, signatures, grant enforcement and explicit user scoping. `CharacterDTO.extensions` is public. The [character service](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/src/services/characters.service.ts) defaults new characters to the owned `mine` library, preserving the creator's existing behavior without passing an undeclared DTO field.
- [Spindle uploads](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/backend-api/uploads.md) explicitly permits a tus 1.0 client using authenticated POST/PATCH requests to `/api/v1/spindle-uploads`, with extension metadata and scoped backend get/delete. This is documented extension networking, unlike the unverified application routes below. The frontend sends one bounded file PATCH, checks the returned offset, blocks redirects and foreign/unrelated upload locations, then sends only the upload ID to the backend. The [published `setAvatar` signature](https://github.com/prolix-oc/lumiverse-spindle-types/blob/fe412d6e378466dfe42a2df16649fa037e428c06/src/spindle-api.ts) and host handler verify the final Characters-gated avatar write. Upload staging itself requires no extra permission.

Both the backend `uuid-v1 >= 1` and `frontend-session-routing-v1 >= 1` capabilities are required. The manifest minimum is now 1.3.0; runtime checks still apply because a version number alone does not prove capability availability. There is no new permission or scanner capability declaration. Frontend requests use a monotonically increasing correlation counter, not a locally generated UUID. Backend replies use only host-supplied account/document identity. Missing support produces a bounded failure with no local generator or broadcast fallback.

Remote plain HTTP remains supported by the UUID path: it requires neither `crypto.randomUUID`, browser crypto, HTTPS, nor a new secure-context feature. Regression tests remove browser crypto entirely. No live remote-host installation or mobile-device test was performed for these changes.

Ordinary DOM construction, browser JavaScript, and non-UUID crypto were not presumed forbidden. [UI placement](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/frontend-api/ui-placement.md) explicitly renders native DOM nodes in host-owned roots. [Backend capabilities](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/getting-started/capabilities.md) describes specific backend restrictions; it does not prohibit every crypto operation.

| Chat delete return discrepancy | [Public host frontend-domain implementation](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/frontend/src/lib/spindle/frontend-domain-api.ts) returns `Promise<void>` and checks Chats permission. SDK 0.6.79 declares optional `delete(): Promise<boolean>`. The call remains on the supported surface; it handles successful void/true and explicit false. This is a verified type discrepancy, not a reason to replace the method with REST. |
| Home compatibility mount / readiness marker | The [host mount registry](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/frontend/src/lib/spindle/mount-points.ts) explicitly retains `landing_chats` as a legacy alias, omitted from SDK 0.6.79. One annotated `@ts-expect-error` records that discrepancy. The existing Home readiness data attribute used to coordinate with the native gallery has no verified extension contract and remains unresolved. Removing it without a supported replacement could restore the scrolling bug. No broader type suppression was added. |
| Existing SoundCloud iframe | **Documented interface mismatch, unresolved.** `soundcloud.ts` creates a raw remote iframe and loads SoundCloud's controller script into the host document. The [DOM helper](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/developer-docs/docs/frontend-api/dom-helper.md) blocks iframe tags in `ctx.dom.createElement` and specifies host-managed sandbox frames. Those frames use allow-scripts only, no allow-same-origin; [child CSP](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/frontend/src/lib/spindle/sandbox-frame.ts) has frame-src/connect-src none. No supported remote-player equivalent was verified. Existing playback code is unchanged; no CSP relaxation, replacement proxy, or sandbox bypass was added. |
| Application REST calls | **Not verified as supported extension interfaces.** Existing same-origin fetch paths listed below remain unresolved. Their existence and session authentication do not establish a Spindle extension contract. This is not a claim that all browser fetch is prohibited. Some underlying CRUD operations have supported SDK equivalents, but the complete import, metadata, reconciliation and preset-binding behavior has not been demonstrated equivalent. |
| Optional `chats.listForCharacter` | Real method in official [frontend domain implementation](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/frontend/src/lib/spindle/frontend-domain-api.ts) and [authority map](https://github.com/prolix-oc/Lumiverse/blob/68c0fa961f0ef4cffa72ee0557aaadffa3ced2f1/frontend/src/lib/spindle/frontend-authority-map.ts); absent from SDK 0.6.79's frontend chat interface. | DOM-dependent guidance/theme detection | `guide-text.ts` depends on rendered labels/sidebar CSS classes; `theme-messages.ts` reads the `lumiverse-user-css` style element. Exact supported parity for current Customize behavior remains unresolved. Adding a permission alone would not sanction raw endpoints. |

### Existing REST interaction inventory

All are under `/api/v1`; this inventory groups actual production fetch call sites, including shared request helpers.

- `card-import.ts`: character import/import-url.
- `character-delete.ts`: DELETE character with operation_id and deletion-operation status reconciliation.
- `connection-tutorial.ts`: saved-connection test.
- `customize-storage.ts`: settings/componentOverrides, settings/wallpaper, images/wallpapers, chat metadata and chat reads.
- `frontend.ts`: chat metadata read, connection read, character summaries, favorite settings read/write.
- `memory.ts`: chat metadata read/PATCH. This edits chat metadata, not the Memory Cortex API.
- `my-chats.ts`: grouped/recent fallback reads, character chats, hidden-from-recent, personas and chat metadata reads.
- `profile-chats.ts`: character-chat fallback read.
- `profile-lorebooks.ts`: world-book and entry reads.
- `prompt-settings.ts`: presets, preset profiles/bindings, chat metadata, connections and settings reads/writes.
- `setup-data.ts`: connections, presets/profile bindings and setup library reads.
- `streaming-settings.ts`: connection/chat reads and configuration/metadata writes.

The creator's former character and avatar application routes, persona creation route, and soundtrack update route are absent from this inventory because those writes are now migrated. `portrait-upload.ts` still uses HTTP for the explicitly documented Spindle upload protocol described above; HTTP use by itself is not an unsupported interaction.
